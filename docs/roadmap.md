# 앱(아이톡톡) 연동 대비 기능 검토 (2026-11-23)

기준: ① 사용자 편의 ② 구현 비용 ③ 위험(잘못된 정보·개인정보·약관) ④ 선행 조건. 요청은 "있으면 좋겠다"가 아니라 득실로 판단한다.

## 가장 큰 편의 문제는 기능이 아니라 데이터
가격 기록이 수작업이라 대부분 제품이 "가격 수집 전/기록 중"이다. 아래 기능은 데이터가 쌓여야 빛난다. 데이터 자동화 경로(공식 API/제휴)가 열리기 전까지는 **핵심 제품의 기록을 꾸준히 쌓는 것**이 최우선이다.

## 0순위: 앱 출시 전에 필요한 선행 항목 (편의가 아니라 전제 조건)
| 항목 | 이유 | 비용 |
|---|---|---|
| 개인정보처리방침·이용약관·제휴(수수료) 고지 페이지 | 앱스토어·구글플레이 심사에 URL이 필요, 쿠팡 파트너스 고지 의무 | 낮음 |
| 데이터 계약: 제품 ID 영구 고정, `schemaVersion`, `updatedAt` | 앱이 같은 JSON을 읽으므로 ID가 바뀌거나 구조가 바뀌면 앱이 깨짐 | 낮음 |
| 판단 값 단일화: `summary.json`(현재 단가·평균·판단) 생성 | 웹과 앱이 각자 계산하면 판단이 달라짐. 목록 화면은 가벼운 요약만 받아 빠름 | 중간 |
| 외부 링크 규칙: 쿠팡·네이버는 시스템 브라우저/쿠팡 앱으로 열기 | WebView 안에서 열면 로그인·결제가 불편 | 낮음(앱 쪽) |

## 1순위: 편의 효과 큼 + 비용 낮음 (웹에 먼저 추가 권장)
1. **제품 딥링크 + 공유 버튼**: `?p=p001`로 제품 상세가 바로 열리고, 배우자·가족에게 공유. 앱↔웹 이동의 기본 장치.
2. **우리 아기 월령 설정(기기에만 저장)**: 한 번 입력하면 월령 가이드가 자동 선택되고 "지금 월령에 맞아요" 표시. 아기가 크면서 계속 쓰는 이유가 됨. 월령별 단계 추천이 아니라 *월령이 확인된 제품만* 표시(잘못된 추천 위험 낮춤).
3. **다크 모드**: 밤 수유·기저귀 교체 때 폰을 쓰는 상황이 많아 체감 큼. 색상 변수가 있어 비용 낮음.
4. **단가 비교 경고**: 단계가 다른 제품을 단가순으로 정렬하면 왜곡됨 → "같은 단계끼리 비교하세요" 안내/단계 선택 유도.
5. **최근 본 제품**: 비교하다 돌아올 때 편함.
6. **링크 점검 자동화(GitHub Actions)**: 쿠팡·네이버 링크가 깨지거나 품절 페이지가 되면 주 1회 알려 줌. 사용자 이탈·실적 손실 방지.

## 2순위: 편의 효과 큼 + 앱 중심 (비용 중간~높음)
| 기능 | 득 | 실·위험 | 판단 |
|---|---|---|---|
| **가격 알림**(관심 제품이 평소보다 저렴) | 재방문 1순위 | 서버 없이 앱이 JSON을 주기적으로 받아 **기기 내 알림**으로 구현 가능. 단, 가격 갱신이 수작업이라 알림 주기가 느림 | 앱에서 구현, 웹은 데이터 준비 |
| **바코드 스캔 → 가격 보기** | 마트에서 바로 비교(체감 매우 큼) | 제품별 바코드(GTIN) 수집·매칭 필요 | 앱 단계에서, 웹은 GTIN 필드 확보 |
| **제품 비교(2~3개)** | 분유·젖병 고를 때 편함 | 모바일 화면 설계 필요 | 관심 목록 연동으로 후순위 |
| **월 예상 비용 계산기** | "한 달에 얼마?" 직관적 | 사용량 가정이 부정확 | 단순 입력식이면 가능, 후순위 |
| **관심 제품 동기화(로그인)** | 웹·앱 공유 | 로그인·서버·개인정보 부담 큼 | 지금은 보류. 앱에서만 저장하고 웹은 읽기 전용 브리지 검토 |

## 3순위/비추천
- 자체 크롤링 가격 수집: 약관·차단 위험(공개 서비스에 부적합)
- 커뮤니티·리뷰: 운영·모더레이션 부담 큼
- 서드파티 분석 스크립트: 개인정보 고지·동의 필요. 대신 쿠팡 파트너스 리포트의 클릭 통계를 활용
- 웹 PWA 설치 안내: 앱이 있으므로 중복
- 로그인 강제: 진입 장벽만 높임

## 호환성 기술 메모
- 안드로이드 앱 링크(앱 자동 열기)는 도메인 루트의 `.well-known/assetlinks.json`이 필요. 현재 주소(`gain1541.github.io/my-website`)는 프로젝트 경로라 불가 → **커스텀 도메인** 또는 `gain1541.github.io` 저장소가 필요.
- 쿠팡 단축 링크(`link.coupang.com`)는 쿠팡 앱이 설치돼 있으면 보통 앱으로 열림.
- 앱이 데이터를 받을 때는 GitHub Pages의 캐시 헤더(ETag)를 활용해 변경분만 받게 한다.
- 제품이 늘고 기록이 쌓이면 `products.json`이 커짐 → 가격 기록은 제품별 파일로 분리 검토.

## 수익 모델·공개 범위 결정 (2026-11-24)
**결정**: 앱은 **무료로 출시하고 광고는 넣지 않는다.** 수익은 제휴 링크로 시작하고, 사용자가 쌓이면 **프리미엄 기능을 1회 결제**로 푼다. 광고는 마지막 선택(신뢰를 해치지 않는 위치에만).

| 구분 | 내용 | 이유 |
|---|---|---|
| **공개(웹사이트)** | 현재 가격·단가 비교·월령 가이드·이유식 요약(블로그 링크) | 방문자를 모으고 쿠팡 파트너스 클릭으로 이어짐 |
| **앱 전용(회원, 프리미엄 후보)** | 가격 알림, 전체 가격 기록, 내 아기 월령 맞춤 추천, 관심 제품 동기화 | 개인화·알림은 가입해야 의미가 있음 |

- 웹은 **로그인 없이 전체 공개**를 유지한다(앱 가입 후 웹으로 넘어오는 것은 허용). GitHub Pages는 링크 접근을 막을 수 없다.
- **앱 전용으로 둘 자료는 이 저장소에 올리지 않는다**(올리는 순간 공개). 이미 공개된 `data/products.json`의 가격 기록을 앱 전용으로 돌리려면 공개 쪽을 최근 값·판단만 남기는 식으로 줄이는 설계가 필요(복사본은 남을 수 있음).
- 앱을 웹사이트만 감싼 WebView로 만들면 앱스토어 심사에서 반려될 수 있으므로 알림·저장 같은 **앱만의 기능**을 둔다(정확한 기준은 출시 전에 심사 가이드 확인).
- **미확인**: 쿠팡 파트너스 약관상 앱 안에서 파트너스 링크를 써도 되는지(CLAUDE.md 남은 일 5번과 함께 확인). 광고를 넣게 되면 광고 SDK의 개인정보 고지·동의(iOS 추적 동의 포함)와 `policy.html` 개정이 필요.
- 앱스토어·구글플레이 결제 수수료율은 출시 전에 확인.

## 이유식 콘텐츠 (검토 중)
- 월령 선택 → 이유식 추천(오늘의 추천) → 재료 손질 요약 → 블로그 원문 링크. 사이트에는 직접 그린 SVG만 쓰고 사진·긴 본문은 블로그에 둔다.
- 소고기 배추죽 글 11개 중 1개를 확인함(재료표·팁·6단계 형식이 일정). **월령·농도·질산염·새 재료 간격은 출처 확인 전에는 넣지 않는다.** 사진 출처(직접 촬영/AI)와 "국내 열량표" 출처, 보관·알레르기 안내 유무는 집에서 원문(PC 브라우저 연동)으로 확인.
- 링크 걸 블로그 글은 **전체공개 + 검색 허용** 상태여야 한다.

## 필요한 결정/자료
- 구글폼 주소(요청·문의), 운영자 표기 방식(개인정보처리방침용)
- 앱 구현 방식(네이티브/WebView/하이브리드)과 출시 OS(안드로이드/iOS)
- 도메인 계획(앱 링크·브랜드), 아이콘 원본
